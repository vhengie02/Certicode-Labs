# Changelog

## 2026-11-14

- The extension's own confirmation dialogs no longer count as a focus loss. On Windows VS Code shows a modal dialog as a separate window, so the editor lost focus and a `focus_lost` event was sent the moment the dialog opened. This hit the "files from another lab or attempt" dialog when a lab starts, the submit confirmation, the exit confirmation and the "connect to this lab server" prompt. Focus changes while one of these dialogs is open, or within a second of it closing, are now ignored. Leaving VS Code at any other time still counts. The fix is in VS Code extension 1.10.1, and students on older builds are now told to update.

## 2026-11-13

- A reopened attempt no longer times out the moment it reopens. Reopening kept the attempt's first start, so on a timed lab the next heartbeat marked it "Timed out" and the student could never resubmit. The time limit now counts from the reopen, and so do time spent and the leaderboard. A team attempt reopened after the team's time ran out goes on alone on that new clock. Reopened while the team's time still runs, it keeps the team's clock and gets no extra time. A live lab's attempt keeps its start, since the shared countdown times it.
- Live labs run on their shared countdown alone. The heartbeat used to end an attempt on the lab's time per student even while the countdown still ran. When the countdown ends, the heartbeat and the inactivity sweep now close the lab, which submits the work, instead of marking it timed out.
- An attempt is timed out only once the minute of grace after its limit has passed, the same minute in which a submit is still taken, and never while a submit is being graded. A lab with no time limit no longer times attempts out after 60 minutes.
- The logo in emails now shows in Gmail. It was sent as an attached picture, which Gmail showed as an empty box. The mark is now drawn in the email itself, so it needs no picture and emails carry no attachment.
- Confirming a Gmail address in Settings has no Confirm button any more. The code is checked as soon as all six digits are in, and Enter still sends it when JavaScript is off.
- The student list on the monitoring page is readable again on screens 1024 to 1279 pixels wide, such as small laptops and split windows. The table's other columns took almost all the width there, so the student's name and email disappeared and the "Student" heading ran into "Status". At those widths each student is now shown as a card, as on tablets. Wider screens keep the table.
- Teammates on a group lab now type in the same files at the same time, each in their own VS Code. What one teammate types shows up in the others' editors as they type, files a teammate adds or deletes appear and go, and a teammate who joins later, or is alone, gets the team's latest files. The leader's submit takes the team's latest edits. A teammate's edit that lands in a file the student hasn't touched is saved for them a second later.
- When a teammate joins with their own, different copy of a file, the team's version replaces it in their editor and their copy is kept in `.certicode/before-shared-typing/`. A session reopened after the team submitted goes on alone, without shared typing. VS Code's Undo can take back a teammate's edit too; the student is warned and can press Redo.
- Each student is still checked only on what they did themselves. A teammate's edit arriving in the editor is not counted as the student's typing, paste or large insert, and the team's line counts credit each line to the student who wrote it, so contribution shares stay per student.
- Edits travel over Supabase Realtime, encrypted with a key only the team's members get, on a channel name nobody can guess. The server stores the edits for late joiners without reading them, and deletes them when the leader submits or the attempt ends.
- Shared typing is off until two settings are added: `TEAM_SYNC_SUPABASE_URL` (the Supabase project URL) and `TEAM_SYNC_SUPABASE_KEY` (its publishable key). Until then, and whenever it can't connect, teammates work in their own copies as before and the sidebar says why. `TEAM_SYNC_MIN_SEND_INTERVAL_MS` (default 400) sets how often a student's edits are sent: every send counts against the Supabase Realtime message quota, once for the sender and once per teammate.
- VS Code extension 1.10.0 adds shared typing. It now ships its libraries inside one bundled file. `npm run sync-check` in the extension folder checks shared typing in a real VS Code window.

## 2026-11-12

- Emails no longer arrive from "${APP_NAME}". Vercel does not fill in `${APP_NAME}` the way a `.env` file does, so the sender name went out as that text. The app now uses the app name when `MAIL_FROM_NAME` is empty or still holds a placeholder.
- Students on a phone or tablet can read a lab but can't start, continue or retake it, since labs run in VS Code. The lab page shows "Open on a computer" in place of the start button, and the module page shows only View lab. The server also refuses a start sent from a phone or tablet, with the error `handheld_device`. An iPad asking for the desktop site looks like a Mac to the server, so the lab page also checks for a touch screen in the browser. Instructors' pages are unchanged.
- Group labs now have a team leader, and the team hands in one piece of work. Only the leader can submit. The AI grades once, and every teammate who opened the lab gets the same score, tasks and feedback. Before, each teammate was graded on their own copy, so a team could get different scores and a teammate who never submitted had no grade. A student with no team still works and submits alone.
- Who leads: the student who starts the team, or the teammate the instructor picks on the Teams page, or else the first teammate to open the lab. The leader can hand the lead to a teammate. If the leader is away, teammates vote: someone leads once more than half of the other teammates choose them. The instructor can change the leader at any time, including during the lab. The lab page and the extension show the leader and the votes.
- A teammate who never opens the lab gets no grade. The monitoring page lists them under their team as "Did not take part". A teammate whose attempt was closed for inactivity while the team was still working does get the team's grade.
- Changing a grade on a team attempt now changes it for the whole team. Untick "Apply to the whole team" to change one student only. Each student is told about their own attempt.
- A team shares one clock on timed labs. It starts when the first teammate opens the lab, so joining late gives no extra time, and it doesn't move when a teammate's attempt closes. Once it runs out, the next teammate to open the lab starts a new team attempt. Earlier team attempts keep their own results. Labs with no time limit and live labs are unchanged.
- A teammate can no longer have another teammate's attempt graded, and a team attempt can't be finished from the website: only the leader's submit in VS Code ends it.
- Team chat now says when a teammate joins or leaves the lab, when someone votes, and when the leader changes.
- VS Code extension 1.9.0 turns Submit off for teammates who don't lead, shows the leader and who is in the lab, and adds Make leader and Vote as leader. Older builds still work: the server refuses their submit and tells the student who leads.

## 2026-11-11

- The "Multiple faces" flag is harder to dodge and raises fewer false alarms. A second person seen in two of the last three camera checks is now flagged. The two checks used to have to be in a row, so someone at the edge of the frame, caught every other check, was never flagged. A large shadow or poster the camera was unsure about could also be taken for the student, which made the real student count as a second person. The most certain face is now the student. While a second person stays, the flag repeats every 30 seconds, not every 40.
- The lab page's face counting now has tests. Run them with `npm test`.

- Verification code, password reset and alert emails now match the look of the sign-in pages. Alert emails used Laravel's default theme. The logo was an inline SVG, which mail clients remove, so it showed as an empty box. It is now a PNG sent with the email. Reset emails also print the link under the button, for mail clients that block buttons.
- The Gmail code in Settings is now typed into six slots. The code is checked as soon as the last digit lands, with no page reload. A wrong code drains out in red with the reason under it, and a right one closes into a tick. Pasting a code and one-time-code autofill both work.
- Disconnecting a confirmed Gmail in Settings now asks for your password, and the route allows 5 tries a minute. It used to take one click, so anyone at an unlocked browser could move your alert emails. Dropping an address that is still waiting for its code needs no password.
- Code, password reset and alert emails are less likely to land in spam. Code emails no longer mention Google or Gmail, which spam filters read as phishing from a sender that is neither. Subjects are now "Your Certicode Labs sign-in code", "Confirm your email for Certicode Labs" and "Reset your Certicode Labs password". Every email also carries a plain-text version, and reset emails greet you by name. Mail still goes out from an address with no domain of its own, so some can still be marked as spam until the app sends from its own domain.
- Delete account in Settings now asks for your password, then your email. It used to need only the email, so anyone at an unlocked browser could delete the account.

## 2026-11-06

- VS Code extension 1.8.9 closes a gap in reload recovery. A window that took 12 to 25 seconds to come back reconnected to the attempt after the lab page had already turned the camera off, so the student kept working with no camera and no flag. The extension now only reconnects within 8 seconds, before the lab page leaves. A slower reload sends the student back through the lab page, and the attempt stays open. Students on older builds now see the warning to update.
- Continue with Google now opens Google's account chooser in a small window over the sign-in page, so people with several Gmail accounts can pick one. It used to sign in with the browser's active account without asking. If the browser blocks pop-ups, the chooser opens in the same tab.
- Motion across the app now follows one set of rules, kept in `resources/css/motion.css`. Menus and pop-ups grow out of the button that opened them and shrink back into it, exits run 20% faster than entrances, and everyday UI no longer bounces. Buttons press in, switches stretch as they slide, tab underlines travel between tabs, list rows arrive in turn, and the theme switch spreads out from its button. On touch screens, toasts swipe away to the right.
- Certicode now has a Privacy Policy, Terms of Service and Cookie Notice at `/privacy`, `/terms` and `/cookies`, linked from the home page, sign-in pages and Settings. They are written for the Philippine Data Privacy Act. The retention periods on the Privacy Policy come from the app's settings, so they can't drift from what the app does.
- Signing up now needs a tick confirming your age and agreeing to the Terms and Privacy Policy. Accounts made earlier are asked once at their next sign-in, and everyone is asked again when `terms_version` in `config/legal.php` goes up. Someone who won't agree can still download their data or delete their account in Settings.
- Students now agree to camera and activity monitoring before the camera turns on for the first time, and the server refuses a camera check without that consent. The agreement is saved with its date and version, included in Download my data, and can be withdrawn in Settings between labs. Run the new migration before deploying.
- The lab page no longer says the camera check "confirms it's you". It only checks that a face is present and never identifies anyone.
- A class past its end date now concludes and issues certificates the first time anyone opens its page. It used to wait for the daily cron, up to a day later.
- Per-file diff counts are now saved, up to 50 files per diff. The server dropped them when it saved a diff, so only the totals survived, and with live updates on, the VS Code sidebar's per-file list could go blank.
- Starting a lab through the API now needs a recent camera check, the same as the lab page. The API route skipped that check for students.
- The README and `.env.example` now match how the app runs. They described Laravel Reverb, which isn't installed, and a cron that runs every minute. Live updates use Pusher Channels, and the Vercel cron runs once a day.
- The session timeline no longer shows "status: error" next to a passing score. That status was the code run, not the grade, so it now has its own "Code run" line that says it doesn't affect the grade. A failed run also shows why it failed, such as a compile error. Submissions made before this change show the run status with no reason.
- On a server without Judge0, a Java lab with no `main` method now counts as a successful code run once it compiles. It used to show as an error. Judge0 servers already treated these labs this way.
- A program that prints unreadable bytes no longer makes a submit look failed. The grade was saved, but the student got a server error instead of their result.
- Camera flags from a dark room now show two pictures side by side, labelled Camera and Brightened. The camera's own frame is often close to black, so it showed instructors nothing. The brightened half is greyscale, and it can show grain or shapes that aren't clear in the room, so the Camera half stays next to it.
- Every "No face", "Multiple faces" and "Too dark" flag now keeps its own webcam picture. When a student stayed out of view, only the first flag in each two minutes had one, so the flags after it showed no proof. An attempt keeps up to 60 pictures of each flag type, about 40 minutes of flags in a row. Flags raised before this change stay without a picture.
- Pasting the same text again in an attempt no longer raises another Paste anomaly while the first flag is still open, even in a different file. Each paste stays on the session timeline, and "Pastes flagged" counts it once. Once an instructor resolves the flag, the next paste of that text raises a new one.
- VS Code extension 1.8.8 counts one-line edits toward the "Large insert" flag. An AI tool that swapped single expressions, such as `return s;` for a one-line answer, used to go unnoticed because each edit had too few words to count as a block. Students on older builds now see the warning to update.
- The results page now shows Large inserts and Low typing effort under Session details, next to Pastes flagged. The student and class staff can see them, but teammates can't. Flags an instructor has cleared are left out. Neither flag changes a grade.
- Group labs now have a team size and a choice of how teams form. Instructors set People per team on the lab form, then pick Students pick, Randomize or I assign them. With Students pick, students choose classmates on the lab page, up to the team size. Picked classmates join right away, get a notification and can leave. Teams lock once a member starts the lab, and the instructor can still change them. With Randomize, enrolled students are drawn into even teams when the lab is saved. The Teams page has a Randomize button for students without a team, such as late enrollees, and it works in every mode. Draw all again redraws every team until one has an attempt. Group labs made earlier keep their teams and have no size limit until one is set.
- The Teams page now counts students without a team correctly. It could list a student who was already in a team, or leave out one who wasn't.
- VS Code extension 1.8.7 stops the lab clock as soon as a student confirms Submit lab. It used to keep running until the grade came back. If the submit fails, the attempt stays open and the clock carries on, counting the time lost. Time spent on a lab no longer includes grading time, for any extension version.
- Instructors can now download a student's submitted files from the Submitted files section of the results page. Each file has a Download button next to Copy code, and an attempt with several files also has Download all, which saves them as a zip with their folders kept. Students can't download from here.
- The instructor dashboard now has a Latest submissions list. It shows the six newest submissions with code across your classes, and each one opens that student's code.
- Instructors now get a notification when students submit a lab. It opens that student's code. A class submitting together sends one notification: submissions within 15 minutes of the last one show on the dashboard and monitoring page only, so a steady stream of submissions sends just the first. When a live lab's timer runs out, the instructor also hears how many open attempts were submitted. Ending a lab or a session yourself sends nothing. Emails follow the Labs setting, which is on by default.
- The camera check now finds faces in much darker rooms. The old brightening step pushed dark faces back to black, so a student in a dim room could be flagged "No face" while sitting at the screen. A face in near-total shadow can still be missed. During a lab, a student in a dark room now sees "Too Dark, Add Light" instead of "Face Searching", so they know how to clear the warning before it reaches 4/4.
- A dark room with movement on camera now raises a softer flag. When no face can be found but the picture keeps moving, instructors see a low-severity "Too dark" flag with the picture instead of "No face", and it doesn't send a notification. A still dark room keeps the "No face" flag. A moving curtain or TV in an empty room can also raise "Too dark", so the picture is there to check.

## 2026-11-05

- VS Code extension 1.8.6 adds a "Large insert" flag. It appears when 100 or more characters of code reach a file without being typed or pasted, such as from an AI tool. An answer written in parts within a few seconds counts as one insert. Instructors can read the code in the session timeline. Generated code and large snippets can also raise it, so it is medium severity at most, and it doesn't change a grade. The Your data section in Settings now mentions it. Older extension builds don't send this flag.
- The "Low typing effort" flag now covers short labs. It used to skip submissions with under 300 characters of new code, so a short answer written by an AI tool with no typing behind it raised no flag. The limit is now 100 characters. The flag still doesn't change a grade.
- The camera check now always needs a detected face. The "Continue in low-light mode" button is gone, because it let an empty dim room pass. A dim room gets a stronger check on a brightened picture, and if no face is found the student is asked to add light and retry. During a lab, a dim room no longer counts as present without a face, so students in very dark rooms may see more absence warnings. Faces too small to be someone at the screen no longer count.
- Three failed camera checks in a row now lock that lab for 15 minutes. The retry count used to run past its limit, such as 4/3, and reloading the page reset it. The server now keeps the count. A lockout flags the student's open attempt with the last picture, or notifies the instructor if there is no attempt yet.
- The Glyphs and Diamonds backgrounds are bolder in light mode. Glyphs is now a terracotta and teal block print on warm sand, and Diamonds is crimson on rose with gold gems.
- A class's page now shows its card background behind the title and key facts, with the same fade as the card.
- Class cards now have pattern backgrounds. Instructors choose one of eight patterns, such as contour lines, moons and stars, or waves, when creating or editing a class, or upload their own picture. Classes without a choice get a pattern automatically. Every pattern has its own colours for light and dark mode, and backgrounds fade out before the text starts. Large pictures are resized before they upload, which also removes their location data.
- Pop-up notifications now wait for the page to finish loading, slide in from the right edge of the screen and slide back out after 3 seconds, or longer for a long message. Error pop-ups still stay until closed. With the "reduce motion" system setting they fade instead.
- VS Code extension 1.8.5 no longer flags a student for moving their own code. Text copied or cut from the same file or another open lab file is not reported as a paste. Code from any other file still is.
- Instructors can now write a rubric on a lab. The AI grader reads it, and students never see it.
- The landing page, sign-in pages and READMEs now describe the product accurately: live and self-paced labs, how certificates are issued, what a paste is compared with, team sizes and instructor approval. The READMEs also name the right AI key and provider.
- Confirmations now open a pop-up in the app's own style instead of the browser's alert box. This covers deleting classes, modules, labs, teams, competencies and accounts, and ending classes, live labs and student sessions. Each pop-up names what it affects, and Cancel is selected first.
- Low-light mode no longer passes a blocked camera. A black or blank picture now fails the pre-lab camera check with a message to uncover the camera or turn on a light, and the low-light option only appears in a dim room. During a lab, the status shows "Camera Blocked", and the warning count stops at 4/4.
- The lab page now leaves camera mode about 12 to 17 seconds after VS Code closes, down from about 40. A window reload that takes longer than 12 seconds now counts as closed: the attempt stays open, and the student starts again from the lab page.
- VS Code extension 1.8.3 opens the starter file under its real name, such as `Strings.java`, when no folder is open. It used to open as "Untitled-1", and a new copy opened on every session sync. The minimum extension version is now 1.8.3, so students on older builds see the update message and instructors see the "Old ext" badge. Those builds still connect.
- Instructors can now read a student's submitted files. A Submitted files section on the attempt's results page lists every file, and the monitoring page links to it from each student. Code that was saved but never submitted is marked as possibly not final. The similarity Compare view now shows each student's full code instead of the first 250 characters.
- The similarity check now compares all of a student's submitted code files, not only the main one, so a copied helper file is caught. Notes and data files like .md, .txt and .json don't count. Existing results update on the next submit or when you click Compare again.
- VS Code extension 1.8.4 also sends code files a student adds or changes in the lab folder during an attempt, so instructors can read them and the similarity check compares them. Older files in the folder, and notes, data and config files, stay on the student's computer. The Your data section in Settings now mentions them.
- The grader now reads all of a submission's code files, not only the main one, so work done in a helper file counts. A file the rest of the code doesn't use doesn't count against the student. If a submission is over 100,000 characters, the files that don't fit are left out and named in the feedback. Existing grades don't change.
- The dashboard's Get started card is now a step-by-step guide. It opens on the first step you haven't done, you can move through the steps with Back and Continue or by clicking a step, and each step is still ticked off by what you actually do. This respects the "reduce motion" system setting.
- The grade on a lab's results page and the "Your progress" percentage on a class page now count up from 0 when the page opens, and their bars, now drawn as a row of small bars, fill up alongside. This respects the "reduce motion" system setting.
- VS Code extension 1.8.1 is out. It stops the false paste flag when a lab's starter files open, and sends up to 10,000 characters of pasted text so instructors can read the whole paste.
- The landing and sign-in pages have a new animated ASCII background, and the extension screenshots on the landing page are up to date.
- The class syllabus shows the date each module and lab was created, in the date format and time zone set in Settings.
- Open labs can have an optional due date. On the syllabus, students see "Due in" before it and "Late by" after it until the lab is done. Late work is still accepted. Live labs show "Locked" until the instructor starts them and "Ongoing" while they run.
- Clicking a section in the Settings menu now scrolls smoothly to it instead of jumping. This respects the "reduce motion" system setting.
- Instructors get three new integrity flags. "Low typing effort" appears when a submission is much larger than what was typed or flagged as pasted. "External file change" appears when a lab file changes outside the editor. "Starter files kept" appears when a lab starts from existing files instead of the starter code. These are prompts to look closer: none of them changes a grade, and group labs skip the typing check.
- VS Code extension 1.8.2 sends these signals, tightens how team chat excuses a paste, and sends the latest typing and diff figures just before a submit.
- Keystroke counts no longer drop back to zero when a student reloads VS Code during a lab.
- Submissions over 100,000 characters or 50 files are now refused with a clear message, and the attempt stays open. A long list of editor errors is shortened for the grader instead of failing the submission.
- The pre-lab camera check now needs a real camera image. A check that sends no image or no face count no longer passes.
- Certificates now depend on grades. A lab counts only when a student reaches the class's new Lab pass score, 75% by default and set in the class settings, and the passing threshold is now the share of labs a student must pass. Grades waiting for an instructor's review don't count until the instructor confirms them. The class page shows labs passed instead of labs done. Certificates already issued stay valid.
- Global search now plays a scramble animation while it loads, then decodes each result into place. It shows a message if the search fails, and respects the "reduce motion" system setting.

## 2026-10-27

- Students now get a results page when a lab attempt ends. It shows their grade, the lab grade that counts (their best attempt), which tasks they finished with the grader's feedback on each, and their stats: time spent, typing speed, lines changed, focus lost and flagged pastes. The lab page opens it as soon as the attempt is submitted, and lists every past attempt with its grade.

Earlier regrades of the same attempt are listed too. Saving the same grade (to confirm a provisional one) now says so instead of "changed from 70% to 70%".
